# 1.0.8 후보: 보기 설정과 설치 앱 업데이트

이 문서는 **미공개 개발 후보**를 설명합니다. 소스 구현, 단위 검사, 브라우저 검사, 실제 설치 파일 배포와 자동 교체 설치는 서로 다른 검증 단계입니다. 문서에 기능이 있다고 해서 운영 배포나 자동 설치 실증이 완료된 것은 아닙니다.

## 보기와 설정

- 분할 보기에서 원문 또는 아웃라인의 오른쪽 위 X는 왼쪽 창을 닫고 렌더링 단일 보기로 전환합니다.
- 렌더링 창의 오른쪽 위 X는 오른쪽 창을 닫고 왼쪽의 원문 또는 아웃라인 단일 보기로 전환합니다.
- 단일 보기에서는 모든 창 X를 숨깁니다. 문서 닫기는 기존 파일 메뉴입니다.
- 전환 전 미완료 입력을 확정합니다. X는 문서를 지우거나 저장하지 않습니다.
- 기본 시작 보기는 렌더링입니다. 설정의 시작 보기 모드에서 원문·아웃라인·렌더링·분할을 선택합니다.
- 시작 보기 변경은 다음 실행부터 적용됩니다. 현재 보기 전환과 X는 시작 설정을 덮어쓰지 않습니다. 구형 `mde.mode` 값은 시작 설정으로 사용하지 않습니다.
- 설정 하단에 md-editor 버전과 공식 웹사이트를 표시합니다. 4개 언어를 지원합니다.
- iframe 부모의 명시적 `mde:mode`는 기존 계약대로 현재 보기를 변경합니다. 설정은 부모 저장·출처 검증·ACK 계약을 바꾸지 않습니다.

## Windows 자동 업데이트의 구현 범위

- 1.0.7 및 이전에는 업데이터가 없습니다. 업데이터 포함 버전은 처음 한 번 수동 설치해야 합니다.
- 설치된 Windows NSIS 앱에서 시작 시 및 실행 중 4시간마다 정식 최신 버전을 확인합니다. 설정에서 자동 확인·다운로드를 끌 수 있습니다.
- 업데이트 소스는 공개 GitHub 저장소 `okpojung/markdown-editor`로 고정합니다. 렌더러나 문서가 임의 업데이트 URL을 전달할 수 없습니다.
- 시험판과 하위 버전으로 자동 이동하지 않습니다. 네트워크 실패는 기존 앱을 종료하거나 문서를 변경하지 않습니다.
- 자동 다운로드를 끄면 지금 확인·다운로드 버튼으로 수동 실행할 수 있습니다.
- 다운로드한 파일의 라이브러리 해시 검사에 더해 Windows Authenticode 상태·발행자·검사 대상 파일 경로를 확인합니다. 설치 직전에도 서명을 다시 확인합니다.
- 서명 검사에 필요한 PowerShell 실패·시간 초과·잘못된 출력·미서명·다른 발행자는 모두 차단합니다. 업스트림의 구형 PowerShell 호환용 검증 생략은 사용하지 않습니다.
- 무료 경로인 SignPath Foundation 인증서를 전제로 허용 발행자를 `SignPath Foundation`으로 맞췄습니다. SignPath 신청·승인과 서명 연결 전에는 Windows 자동 설치가 동작한다고 주장하지 않습니다. 신청에는 코드 서명 정책을 홈페이지에 게시하고, 릴리스마다 수동 승인을 거치며, 다단계 인증을 쓰는 등의 조건이 있습니다.
- 설치 후 재시작 버튼은 네이티브 확인 창을 거칩니다. 입력을 확정한 뒤 미저장 문서가 있으면 설치를 차단하고 먼저 저장하도록 안내합니다. 버리고 설치하는 경로는 제공하지 않습니다.
- 승인 후에도 문서 상태를 다시 확인하고, 설치 구간에는 편집 창과 새 문서 열기 전달을 막습니다. 실패하면 편집 창을 복구합니다.
- NSIS 설치는 확인 이후 무인 모드로 실행하되 필요한 Windows 관리자 권한 창은 우회하지 않습니다.
- 앱 종료만으로 설치하지 않습니다. `autoInstallOnAppQuit=false`를 유지해 기존 미저장 문서 보호를 건너뛰는 종료 훅을 만들지 않습니다.
- 개발 실행, 일반 실행 CI probe, 격리 smoke에서는 업데이트 네트워크·설치를 비활성화합니다.

## 서명·플랫폼 제한과 남은 검증

현재 공개본은 Windows 퍼블리셔 서명과 macOS Developer ID/공증을 갖추지 않았습니다. 이 후보는 서명을 우회해 미서명 파일을 자동 실행하지 않습니다.

- **[blocked] Windows 실제 자동 교체 설치**: 정식 코드 서명 인증서, 실제 발행자 확인, 서명된 다음 버전 설치 파일과 구버전→신버전 설치·재시작·파일/설정 보존 검증이 필요합니다. 개인·모든 사용자 설치 범위를 각각 확인해야 합니다.
- **[blocked] macOS 자동 업데이트**: Developer ID 서명·공증, ZIP 업데이트 패키지·플랫폼별 메타데이터 및 실제 전환 검증이 필요합니다. 이번 후보에서는 수동 업데이트 링크를 제공합니다.
- **Linux AppImage**: AppImage 실행본에서만 자동 확인·다운로드·설치 후 재시작을 사용합니다. 발행 메타데이터 `latest-linux.yml`의 sha512와 ELF 형식을 검사합니다. 이 후보에서는 실제 이전 버전 AppImage를 새 버전으로 교체하는 시험을 아직 수행하지 않았습니다.
- **Linux DEB**: 관리자 권한 설치가 필요해 자동 설치 방식을 따로 설계해야 하므로 수동 업데이트입니다.
- **macOS**: 이번 결정에 따라 수동 업데이트를 유지합니다. 자동 업데이트에는 Developer ID 서명과 공증이 필요합니다.
- Windows 별도 표준 계정 로그인과 UAC 취소·복구 실증은 별도 검증 대상입니다.
- 인증서 개인키·비밀번호를 소스, 로그 또는 대화에 넣지 않습니다. 유료 인증서 구매나 저장소 비밀 설정은 이 소스 수정에 포함하지 않습니다.

## 업데이트 배포 메타데이터

- electron-updater와 YAML 파서는 앱 의존성으로 버전을 고정합니다. Windows의 게시 대상만 구성하며 빌드 명령의 `--publish never`는 유지합니다.
- 1.0.8 이후 Windows 빌드 증거에 `latest.yml`을 포함합니다. 설치 파일과 함께 바이트 수·SHA-256을 기록합니다.
- 릴리스 준비기는 기존 main tree·성공한 4플랫폼 실행·설치 증거 확인을 유지합니다. 새 시작 보기 검사 62개와 업데이트 smoke 상태도 확인합니다.
- `latest.yml`의 버전·단일 파일명·크기·SHA-512가 같은 검증 빌드의 Windows EXE와 일치해야 초안에 올립니다. 임의 외부 URL이나 다른 버전 메타데이터는 거부합니다.
- 차등 다운로드는 비활성화합니다. blockmap 없이 검증된 EXE 전체를 내려받습니다.
- 공개 릴리스 생성은 검증된 **초안** 준비와 구분합니다. 이 후보의 문서·로컬 검사만으로 실제 릴리스 준비나 공개가 끝난 것은 아닙니다.

- `desktop/test/startup-view.test.cjs`: 기본값·기존 보기 저장 무시·X 배치·버전 일치·정확한 회귀 증거·메타데이터 변조 거부.

- 새로운 네이티브 설치 파일의 빌드·설치 CI와 실제 업그레이드는 로컬 Node/브라우저 검사와 별도로 수행해야 합니다.

EMM 저장소·운영 서버·인증·첨부·DB·DNS는 이번 후보에서 변경하지 않습니다.
